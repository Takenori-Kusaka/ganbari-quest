## 2. データ処理の概要

### 2.1 処理の目的

子供の日常活動（お手伝い・学習・運動等）をポイント化し、ゲーミフィケーション手法で動機付けを行う家庭向け Web アプリケーション。

### 2.2 処理の法的根拠

- **GDPR Art. 6(1)(a)**: 保護者の明示的同意（サインアップ時に利用規約・プライバシーポリシーへの同意を取得）
- **GDPR Art. 8**: 子供のデータ処理に対する保護者同意（本サービスは保護者が管理者として利用し、子供のプロフィールを作成する）

### 2.3 処理するデータ

| カテゴリ | データ | 感度 | 保存先 |
|---------|--------|------|--------|
| 子供プロフィール | ニックネーム、年齢、UIモード | 低〜中 | Aurora DSQL |
| 活動記録 | 活動名、記録日時、獲得ポイント | 中 | Aurora DSQL |
| ステータス | レベル、経験値、連続日数 | 低 | Aurora DSQL |
| 実績 | 獲得実績・称号 | 低 | Aurora DSQL |
| アバター画像 | アップロード画像（過去に保存された画像を含む） | 中 | S3 |
| 保護者メールアドレス | 認証用 | 高 | Cognito User Pool |
| 決済情報 | クレジットカード情報 | 極高 | Stripe（外部、自社保存なし） |

保存先は運営者が提供する SaaS の構成を示す。セルフホスト構成（NUC）では同じデータが利用者宅内の SQLite ファイルに保存され、運営者は保持しない。

### 2.4 収集しないデータ

- 子供の本名・住所・電話番号
- 顔写真・動画
- 位置情報・GPS データ
- 他サービスとの連携データ
- 広告 ID・トラッキング情報

### 2.5 データ保存期間（Storage Limitation, GDPR Art. 5(1)(e)）

本サービスはプランに応じた履歴保持期間を設定し、期限を超過したデータを**日次バッチで物理削除**する。
これは GDPR Art. 5(1)(e)「保存制限の原則」および pricing page の公開約束を履行するための仕組み。

| プラン | 活動ログ・ポイント履歴・ログインボーナスの保持期間 | 対象テーブル |
|--------|------------------------------------------|------------|
| free | **90 日** | `activity_logs`, `point_ledger`, `status_history`（#3330: login_bonuses は counter 縮約で対象消滅、ADR-0049 改訂） |
| standard | **365 日** | 同上 |
| family | 無制限（削除なし） | 同上 |

**削除フロー:**

1. 日次バッチ `retention-cleanup-service.cleanupExpiredData()` が全テナントを走査
2. 各テナントのプランティアを `resolveFullPlanTier()` で解決（トライアル考慮）
3. プランの cutoff 日（free=90 日前 / standard=365 日前）を算出
4. 各子の 3 テーブルから `recorded_date < cutoffDate` を物理削除（復元不能）
5. family プラン（トライアル含む）はスキップ

**削除されない（恒久保持）データ:**

- `children` / `activities` / `settings` 等のマスタ（データの意味を破壊するため）
- `report_daily_summaries` 等の集計テーブル（月次レポートは全期間の集計を前提）
- **ポイント残高**（BALANCE）— 明細は消えるが残高は維持（子供の UX 破壊を避けるための #729 の設計判断）
- `child_achievements` / `special_rewards` / `stamp_cards` 等（現時点では retention 範囲外、将来再検討）

**多層防御:**

バッチが失敗した場合のフォールバックとして、`applyRetentionFilter()` による読み取り時の表示フィルタも並行して動作する。これにより cutoff を超えたデータが UI に露出することはない。

**実装の詳細**: [08-データベース設計書.md §6.5](08-データベース設計書.md) / [ADR-0028（archive）](../decisions/archive/0028-retention-physical-delete.md)

### 2.6 アカウント削除時のライフサイクル

- ユーザーによるアカウント削除: **30 日猶予期間**後に認証・テナント・全レコードを物理削除（ADR-0022）
- 違反アカウント強制削除: OPS 画面から即時削除
- 削除対象: DB 全レコード + S3 アセット + Cognito ユーザー

## 3. リスク評価

### 3.1 リスクマトリクス

| リスク | 影響度 | 発生可能性 | 対策後リスク | 緩和策 |
|--------|--------|-----------|------------|--------|
| 不正アクセスによるデータ漏洩 | 高 | 低 | **低** | Cognito JWT認証、テナント分離、TLS 1.2+、IAM最小権限 |
| クロステナントデータ混入 | 高 | 極低 | **極低** | 複合 PK `(tenant_id, id)`、tenant-scoped repository を単一強制点として全層で tenantId 必須、CI fitness function で述語欠落を検出（ADR-0063） |
| 子供データの目的外利用 | 高 | 極低 | **極低** | データ最小化方針、広告/トラッキング非使用、第三者提供なし |
| アバター画像経由の攻撃 | 中 | 低 | **極低** | Sharp re-encode、マジックバイト検証、CSP、Content-Type ホワイトリスト |
| ブルートフォース攻撃 | 中 | 中 | **低** | IP ベースレートリミッター、Cognito パスワードポリシー |
| セッションハイジャック | 高 | 低 | **極低** | HttpOnly/Secure/SameSite Cookie、HSTS、短い有効期限 |
| データ削除の不完全（アカウント削除） | 中 | 低 | **低** | 30日猶予期間後の自動完全削除（DB + S3 + Cognito） |
| 保存制限原則違反（GDPR Art. 5(1)(e)） | 中 | 中→**低** | **低** | プラン別 retention cleanup 日次バッチ（free 90 日 / standard 365 日）＋ 表示フィルタの二層防御（ADR-0028） |
| バックアップ内の残存データ | 低 | 中 | **低** | S3 バックアップ30日自動削除、AWS Backup 3日保持 |
| サブプロセッサーでのデータ漏洩 | 高 | 極低 | **低** | AWS/Stripe は GDPR 準拠済み、DPA 締結確認済み |
| 内部関係者による不正アクセス | 中 | 極低 | **極低** | IAM ロール分離、CloudWatch ログ監視 |

### 3.2 リスク評価基準

- **影響度**: 低（不便）/ 中（精神的苦痛）/ 高（重大な権利侵害）
- **発生可能性**: 極低（理論上のみ）/ 低（技術的に困難）/ 中（一般的な攻撃で可能）/ 高（容易）

## 5. サブプロセッサー

| サービス | 処理内容 | GDPR 対応 | DPA |
|---------|---------|----------|-----|
| AWS（Aurora DSQL, S3, Lambda, Cognito） | データ保存・処理・認証 | [AWS GDPR Center](https://aws.amazon.com/compliance/gdpr-center/) | AWS DPA（オンラインで締結可能） |
| AWS Bedrock | 生成 AI によるテキスト補助（活動 / ごほうび / おうえん / チェックリストの提案、レシート画像からの金額読み取り） | 同上 | 同上 |
| Stripe | 決済処理 | [Stripe Privacy](https://stripe.com/privacy) | Stripe DPA（利用規約に含まれる） |
| GitHub | ソースコード管理・CI/CD | [GitHub DPA](https://github.com/customer-terms/github-data-protection-agreement) | GitHub DPA |

**生成 AI に渡す内容**: リクエストに載るのは、固定の指示文と、保護者が入力欄に自分で書いた自由記述テキスト、またはレシート画像だけである。子供のニックネーム・年齢・家族内一意 ID・活動履歴をアプリケーションが載せる経路は持たない。運営者が提供する SaaS 側の生成 AI は自社 AWS アカウント内の Bedrock のみで、運営者の環境の外にある生成 AI へ子供のデータを出す経路は無い（境界は `tests/unit/architecture/external-ai-client-boundary.test.ts` が固定する）。セルフホスト構成（NUC）では利用者の判断で外部の生成 AI を設定できるが、その場合の管理者は利用者自身であり運営者は経路を持たない。

## 6. 越境データ移転

| データ | 移転先リージョン | 根拠 |
|--------|----------------|------|
| Aurora DSQL データ | us-east-1（米国） | AWS DPA + SCC（標準契約条項） |
| S3 アセット | us-east-1（米国） | AWS DPA + SCC |
| Cognito ユーザー情報 | us-east-1（米国） | AWS DPA + SCC |
| Bedrock への推論リクエスト | us-east-1（米国） | AWS DPA + SCC |
| 決済情報 | Stripe のデータセンター | Stripe DPA + SCC |

AWS は EU-US Data Privacy Framework 認証済みであり、SCC（Standard Contractual Clauses）もカバー。

Bedrock は **cross-region inference profile (`us.` prefix) を使う**。実体は `infra/lib/compute-stack.ts` の `BEDROCK_MODEL_ID = 'us.anthropic.claude-haiku-4-5-20251001-v1:0'` で、推論は profile の member region（us-east-1 / us-east-2 / us-west-2）のいずれかで行われる。IAM は当該 inference profile ARN と member region の foundation-model ARN に限定する。

> 本節は #4944 で実装に合わせて訂正した。旧記述は「base model ID を us-east-1 に固定し cross-region inference profile を使わない」としていたが、実装は profile 経由であり、privacy.html 第 10 条（「生成 AI の推論のみ、米国内の複数リージョン us-east-1 / us-east-2 / us-west-2 で処理される場合があります」）だけが実装に追随していた。移転先の記述が 3 箇所で食い違ったままだった。

### 6.1 `BEDROCK_MODEL_ID` は越境整理の制御点である

**モデル ID を変えると越境の法的整理が変わる。** 実装定数の変更として扱ってはならない。

AWS の abuse detection では、既定は Zero Data Retention（入出力を保存せず、AWS のオペレータも参照しない）だが、**モデル単位の例外リスト**があり、そこに載るモデルは全トラフィックを最大 30 日保持し、フラグが立つと AWS による人間のレビュー対象になる（2026-09-12 時点で Claude Fable 5 / 5.1、OpenAI GPT 系が該当）。例外リストのモデルに切り替えると「AWS が当該個人データを取り扱わないこととなっている」（PPC Q7-53 / Q12-3 のクラウド例外）が成立しなくなる。

- 現行の `claude-haiku-4-5` は例外リスト外（2026-09-12 実測）
- 例外リストは契約条項ではなく AWS のドキュメントページ上の記述であり、**モデル単位で随時変わる**
- 画像入力はモデル非依存で CSAM 検知が働き、フラグ時は AWS が保存・レビューしうる（本サービスは領収書画像を送る。§5 の送信範囲と合わせて認識しておく）

→ モデル ID を変更する PR は、本節と privacy.html 第 10 条の「移転先国」の記述を同時に見直すこと。判断の根拠は [rationale/19-cross-border-consent-rationale.md](../rationale/19-cross-border-consent-rationale.md) §3。

## 7. 評価結論

### 7.1 総合評価

本サービスは子供の個人情報を処理するため GDPR Art. 35 に基づく DPIA が必要であるが、以下の理由により**リスクは適切に緩和されている**と評価する:

1. **データ最小化**: 子供の本名・住所・位置情報等の高感度データを収集しない
2. **テナント分離**: 複合 PK `(tenant_id, id)` + tenant-scoped repository の単一強制点 + CI fitness function により家族間のデータ分離を保証（ADR-0063）
3. **暗号化**: 通信（TLS 1.2+）および保存データ（Aurora DSQL / S3 のサーバーサイド暗号化）の両方で保護
4. **権利保障**: アクセス・訂正・削除・ポータビリティの全権利に対応済み
5. **同意管理**: バージョン管理付きの同意取得・再同意フローを実装済み
6. **削除の完全性**: 30日猶予期間後にDB・S3・Cognitoから完全削除

### 7.2 残留リスクと受容

| 残留リスク | レベル | 受容理由 |
|-----------|--------|---------|
| バックアップ内の残存データ（最大30日） | 低 | S3ライフサイクルで自動削除。30日は合理的な保持期間 |
| Lambda インスタンス間のレートリミッター非共有 | 低 | 現在のトラフィック規模では実質的な影響なし |
| us-east-1 リージョンでのデータ保存 | 低 | AWS DPA + SCC で法的根拠を確保。EU展開時に eu-west-1 への移行を検討 |
| レシート画像に写り込む付随情報（店舗名・購入品目等）の Bedrock 送信 | 低 | 自社 AWS アカウント内・us-east-1 に閉じた処理で、画像は金額読み取り後に保存しない。IAM は 1 つの base model ARN に限定 |
