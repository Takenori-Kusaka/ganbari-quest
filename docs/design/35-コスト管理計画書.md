## 1. 設計背景

個人開発の SaaS は、売上が立つ前にクラウド費用が膨らむと続けられない。月額の上限を決め、超えそうになったら人が気づける仕組みを持つ。金額の閾値は CDK にあり、本書はその方針と「どこを見ればよいか」を定める。

## 2. 設計原則

- **金額の閾値はコードが SSOT。** 本書に金額を複製しない（複製すると CDK の変更に追随しない）
- **無料枠と従量課金で収まる構成を選ぶ。** 常時課金の構成（Provisioned Concurrency 等）は、使う理由が明文化されるまで入れない
- **気づく手段は通知に寄せる。** Cost Explorer API は 1 リクエストごとに課金されるため、画面からのリアルタイム照会はしない（`infra/CLAUDE.md` §AWS Cost Explorer API 使用制限）

## 3. コストの監視

| 仕組み | 対象 | 定義の SSOT |
|---|---|---|
| AWS Budgets（月額全体） | アカウント全体の月額。実績と予測の段階通知 | `infra/lib/ops-stack.ts`（`MonthlyBudget`） |
| AWS Budgets（DSQL） | DSQL の月額と、そのバックアップの月額 | `infra/lib/dsql-stack.ts`（`DsqlBudget` / `DsqlBackupBudget`） |
| Cost Anomaly Detection | 異常なコスト増加 | IaC 外。AWS アカウント既定のモニターを使う（13 §3.4） |
| 月次コスト監査 | 月初に費用とリソースの棚卸しを出力 | `.github/workflows/cost-audit.yml` |

---

## 4. コストを抑える構成

| 施策 | 実体 |
|---|---|
| Lambda は ARM64 (Graviton) で動かす | `infra/lib/compute-stack.ts` |
| Provisioned Concurrency を使わない（コールドスタートを許容する） | 同上。レイテンシへの影響は [32-SLI-SLO定義書](32-SLI-SLO定義書.md) の p99 目標で見る |
| DB は Aurora DSQL（リクエスト量に比例する課金）。クエリは DPU を増やさない規約に従う | ADR-0065 |
| 静的アセットは CloudFront でキャッシュし、S3 から配る | `infra/lib/network-stack.ts` |
| ログは保持期間を決めて自動削除する | 13 §3.4 / 17b-ログ設計書 §8 |
