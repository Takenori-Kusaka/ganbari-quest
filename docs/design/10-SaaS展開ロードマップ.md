# SaaS展開ロードマップ

## 1. 設計背景

がんばりクエストを家庭内の個人開発アプリから有償の SaaS として展開する。この文書が無いと、次の 2 つが決まらない。

- **優先度に迷ったときに戻る場所**。Issue は常に数十件 open で、どれも「重要」に見える。何をもって展開が成功したと言うかが無いと、目についたものから手を付けることになる
- **有償での外部公開をいつしてよいか**。課金・データ保全・問い合わせ窓口のどれかが本番で壊れていても、LP を公開すれば顧客は来る。最初にその経路を通るのが、お金を払った実在の顧客になってはいけない

## 2. 設計原則

1. **判断軸だけを持つ**。個別 Issue の進捗・価格・コストの値はこの文書に書かない（それぞれの SSOT を指す）。書くと、この文書だけが古くなる
2. **公開の可否は実演で決める**。「実装済み」「staging で通った」は根拠にしない。本番で 1 周した記録だけを根拠にする
3. **ストア展開・英語化・法人化は収益が出てから**。予算 (C) > 品質 (Q) > スピード (D) の順で判断する

## 3. 成功定義

期限は **2026-10-31**。優先度に迷ったらここに戻る（PO が設定）。期限を過ぎたら、PO が結果に合わせて本節を改訂する。

| # | 状態 | 対応する EPIC |
|---|---|---|
| 1 | 有料課金が取りこぼしなく一巡する（checkout → webhook → プラン反映 → 期末解約が人手を介さずに回り、請求ミスの返金は [返金 runbook](../runbooks/refund-and-billing-incident.md) どおりに回せる） | #4117 E1 / #4118 E2（staging）/ #4580 G1・G2（本番 live・返金手順） |
| 2 | 獲得した家族が離脱しない（招待の受諾 / おやカギ / JST の日付境界に関わる critical が本番で再現しない） | #4120 E4 |
| 3 | サインアップ 20 名/月に到達する導線が生きている | [34-V2MOM.md](34-V2MOM.md) |
| 4 | データを失わない（本番のバックアップを実機で 1 サイクル検証済み・off-site に控えがある） | #4119 E3（NUC）/ #4580 G7（有償 web の復元実演） |
| 5 | 1 人 + AI の開発ループが 1 日で回る | #4121 E5 |

各 EPIC の進捗は GitHub の Issue が SSOT。

## 4. 有償サービスインの条件

有償での外部公開の可否は **EPIC #4580（有償サービスイン Go/No-Go）** で判定する。本番 live での課金 1 周（G1）が通るまで、有償での外部公開はしない。

条件（G 項目）の一覧と実施の記録は #4580 の本文が SSOT。本書には条件の中身も件数も写さない（条件が足されたときに、本書だけが古くなる）。
