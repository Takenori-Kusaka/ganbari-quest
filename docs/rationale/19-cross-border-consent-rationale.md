# 越境データ移転の同意 設計経緯

## 議論の発端

- **日時**: 2026-09-12
- **発端 Issue / セッション**: #4944（PO セッション）。前提となる実装は #1638（同意の導入）/ #4497（証跡と OAuth 経路の穴を塞いだ）
- **問題意識**: 規約改定にともなう再同意 (`/consent`) で「外国にある第三者への提供」の同意項目を見た利用者から、**「逆に不安になった」「AWS や Google と言われても何をされるのかよくわからない」**という声が届いた。安心させるための同意が逆効果になっていた。

`CURRENT_PRIVACY_VERSION` を 2026-09-10 に上げたことで全既存利用者が `/consent` を通過している最中であり、声はそのタイミングに集中していた。

---

## 前提の確定 — この同意は本当に必要なのか

文言を直す前に、**同意が法的に必要なのか**を PPC の一次情報で確認した。結果、経路ごとに要否が違うことが分かった。「AWS / Stripe / Google」を 1 つのチェックボックスに束ねていたこと自体が誤りだった。

| 経路 | 一次根拠 | §28 同意 |
|---|---|---|
| S3 / Aurora DSQL / Bedrock | クラウド例外（[Q7-53](https://www.ppc.go.jp/all_faq_index/faq1-q7-53/) / [Q12-3](https://www.ppc.go.jp/all_faq_index/faq1-q12-3/)）。AWS カスタマーアグリーメント §1.4（日本語公式訳、2026-08-14）+ AWS DPA §2・§3 | **不要** |
| Cognito（保護者メールアドレス） | 同じ AWS 契約下だが、AWS 自身が Cognito の data protection ページで「入力したデータが診断ログに取り込まれる可能性がある」と記載。認証**処理**サービスであり Q7-53 が想定するストレージ類型に素直に収まらない | **判断不能（要専門家確認）** |
| Google OAuth | 本人が直接 Google に渡す。[Q8-10](https://www.ppc.go.jp/all_faq_index/faq1-q8-10/)「A 社が取り扱っていないのであれば…B 社が直接ユーザーから取得したこととなる」の論理 | **不要（推定）** |
| Stripe（決済） | クラウド例外は**不成立**（Stripe DPA §2 が独立データ管理者と明記）。Stripe, LLC が[グローバル CBPR 認証](https://www.globalcbpr.org/privacy-certifications/directory/)保有（TrustArc / Jul 2025–Jul 2027）→ 施行規則 16 条 2 号該当（[GL 外国第三者提供編 4-3](https://www.ppc.go.jp/personalinfo/legal/guidelines_offshore/)） | **§28 は不要。ただし §27 が残る** |

**AWS 自身の立場**: 公式日本語ホワイトペーパー（2022-03 改訂）が Q7-53 を名指しし「お客様と AWS との間で合意した場合を除き、AWS のサーバーに保存された個人情報を AWS が取り扱うことはありません」と明記している。ただし同書は「いかなる契約の一部も構成しない」と断っており、根拠はあくまで契約条項（CA §1.4 / DPA §2・§3）側にある。PPC が AWS 個別を是認した事実は無い（PPC は特定事業者を認定しない）。

**Stripe で見落としやすい 2 点**:

- GL 2 は「法第 28 条第 1 項の適用がないため…本人の同意を得る必要はない。**ただし、当該第三者への個人データの提供に当たっては、法第 27 条の規定による次の（ア）から（エ）のいずれかの方法による必要がある。**」と書く。Stripe は独立管理者なので（エ）委託構成が素直に使えず、実質（ア）本人の同意が残る
- GL 6 は「**本人の同意を根拠として…提供した場合には、当該第三者が基準適合体制を整備していると認められる場合であっても、法第 28 条第 3 項に基づく措置等は求められない。**」と書く。CBPR 依拠を選ぶと §28(3)（規則 18 条）の年 1 回以上の確認と 7 項目の情報提供義務が永続し、2027-07 の認証失効も監視し続けることになる。**同意を取る方が総運用コストは安い**

**クラウド例外が成立しても消えない義務**: 法 23 条（外的環境の把握）と法 32 条 1 項 4 号・施行令 10 条 1 号（外国の名称 + 講じた措置を本人の知り得る状態に置く）。[Q10-25](https://www.ppc.go.jp/all_faq_index/faq1-q10-25/) は「**日本国内に所在するサーバに個人データが保存される場合においても同様です**」とも書いており、リージョンを東京に移してもこの義務自体は消えない。

## 実装の事実 — Stripe に個人データをほぼ送っていない

`src/lib/server/services/stripe-service.ts` の Checkout Session 作成が Stripe へ送るのは `metadata: { tenantId, planId }` とプラン名だけで、`customer_email` を設定していない。メールアドレスとカード番号は利用者が Stripe のホストページへ直接入力し、当方サーバーを通らない。`stripeCustomerId` は webhook で戻る値である。

この事実は文言設計を決定づけた。**抽象的な保証（「売りません」）ではなく、検証可能な事実（「カード番号は当方のサーバーを通りません」）を書ける**からである。

## 検討した代替案

| 案 | 概要 | 検討した理由 |
|----|------|-----------|
| 案 A | 文言だけ和らげる | 最小変更。既存の同意フローに触らない |
| 案 B | 同意を全面撤去し開示（外的環境の把握）に一本化 | クラウド例外が成立するなら、そもそも不要な同意を求めていることになる |
| 案 C | ap-northeast-1 へ移設して「米国」を画面から消す | #1638 当時と違い Aurora DSQL 東京は提供済み |
| 採用案 | 根拠ごとに分解し、第一層を「何が起きる / 起きない」にする。事業者名・国名・制度は第二層（privacy.html 第 10 条）へ | 不安の発生源が「同意の存在」でも「情報の不足」でもなく、**提示の構造**にあると判明したため |

## 棄却理由

- **案 A 棄却理由**: 不安の原因は語調ではない。(1) 否定形 3 連（売らない・追跡しない・学習に使わない）が見出し直後に置かれ、打ち消す対象のリスクを先に想起させていた (2) 事業者名の羅列が「自分に何が起きるか」に変換できない (3) 目的の違う 3 経路が 1 つの同意に束ねられている。語調を変えてもこの 3 つは残るため再発する。
- **案 B 棄却理由**: Stripe で §27 の根拠が消える。GL 2 の（ア）〜（エ）のいずれかが必要で、Stripe は独立管理者のため（エ）委託が使えない。加えて Cognito の扱いが公開文書だけでは確定できない。同意をゼロにするには専門家確認が前提になる。
- **案 C 棄却理由**: Q10-25 より、外国事業者のクラウドである限り「外的環境の把握」の義務自体は消えない。得られるのは「米国」という語を画面から消せることだけで、インフラ全体（Lambda / Cognito / CloudFront）の移設コストに見合わない。判断自体は #4944 の D5 として残す。

## 採用案とその理由

**第一層（同意画面）= 何が起きる / 起きないを平易語で。第二層（privacy.html 第 10 条）= 法定記載。**

施行規則 17 条 2 項の 3 情報（移転先国 / 当該国の制度 / 移転先が講ずる措置）は第二層で提供する。PPC A12-10 が URL による提供を認めているため、同意の有効性は損なわれない。

第一層に置く 4 文は、いずれも実装で裏が取れる事実に限った（ICO Age Appropriate Design Code Standard 4: *"does not promise protections or standards that are not routinely upheld"*）。

| 文 | 根拠 |
|---|---|
| 暗号化してお預かりする / ほかのご家庭から見えない | テナント分離（ADR-0063）+ 保存時・通信時の暗号化（DPIA §4.1） |
| 決済会社に渡るのはプラン名とご家族を表す記号だけ / カード番号は当方サーバーを通らない | `stripe-service.ts` が `customer_email` を設定せず metadata のみ送る |
| 広告・第三者販売・AI 学習への流用は行わない | DPIA §5 + `external-ai-client-boundary.test.ts` |
| 退会するとサーバーから削除される | 退会時の物理削除（DPIA §2.6） |

### なぜこの構造なのか（行動科学と当局ガイダンス）

- **保証文を足すと不安が増える**: Marreiros et al. 2017 (JEBO) は、企業の**肯定的**なプライバシー姿勢を顕在化させた場合ですら、プライバシーに言及しない場合より開示が保守的になることを示した。John, Acquisti & Loewenstein 2011 (JCR) も「保証文はプライバシー懸念を呼び起こす手がかりとして作用する」と結論している。**打ち消しを増やす方向の対処は効かない**
- **事業者名の羅列は読まれない**: Nouwens et al. 2020 (CHI) では、ベンダー・目的のリストが提示された 560 回のうち **68.6% が完全に無視**された。"anything not immediately visible to the user… might as well not exist"
- **カテゴリ語は理解されず、結果ベースの記述だけが効く**: Balash et al. 2024 (SOUPS, n=1,505) は `identifiers` `linked` 等の語が理解されない一方、「金融情報を本人に紐づけて収集」のような結果ベースの記述がリスク知覚を大きく動かすことを示した。同研究は "Data not collected" 表示に対する *"I assume it is lying to some extent"* という回答も記録している
- **当局の明文**: WP29 WP260 ¶10 は法定項目に**加えて**「この処理が本人にどんな effect を与えるか」を平易語で明示せよと求め、¶36 は第一層に「最も影響が大きい処理・驚かせる処理」を置けとする。本設計はこれに沿う

### 実例の相場観

日本の子ども／家庭向けサービス（みてね・コドモン・Classi・ぴよログ・LINEヤフー・任天堂）を全文取得して確認したところ、**海外保管について独立した同意チェックボックスを立てている例は 1 件も無かった**。

- **MIXI**: 節タイトルが「外国で個人情報を取り扱う場合の措置」。「事業者は保存データにアクセスできない技術的措置 → 制度とポリシーを確認済み → 所在地は日本／米国／EU 圏」の順。**「中身は見られない」を先に言ってから国名を出す**
- **任天堂**: 独立ページに「提供先名称／所在国／提供先が講ずる措置」の表。確認が取れないセルには「提供先に確認できていないため、情報提供できません。」と書く
- **LEGO**: 短縮版と正式版の 2 層。短縮版では海外保管を章立てせず 1 文に埋め込む
- 逆方向の教訓として、LINE は 2021 年に保管国を書いていなかったことが報道で発覚し全列挙体制へ移行した。**書かないことはリスクを消さない**

なお、法的に不要な同意を「同意しないと進めない」形で全員に出す設計は、消費者庁「いわゆる『ダークパターン』に関する取引の実態調査」（2025-04-07、国内 102 サイト）の「事前選択」「強制登録」類型に接近する。ICO も「拒否されても別根拠で処理を続けるなら、同意を求めることは *misleading and inherently unfair* であり、偽の選択肢と支配の錯覚を与えるだけ」と書く（GDPR の規律であり日本市場の本サービスに直接は及ばないが、機序の説明としては正確）。

## 残された懸念・フォローアップ

すべて #4944 の「PO 判断事項」として残している。同意記録のスキーマ（`ConsentType`）と再同意フローに触るため、本 rationale を書いた PR とは分けた。

- [ ] **同意対象を Stripe（決済）に限定するか** — AWS 保存分と Google OAuth は同意から外し、開示に降ろす。#4944 D1
- [ ] **同意のタイミングを決済導線へ移すか** — 現状は無料で使い始めるだけの利用者にも Stripe への提供を同意させている。決済を一度も通らない人には提供自体が発生しない。#4944 D2
- [ ] **Cognito（メールアドレス）の扱い** — 公開文書では判断不能。専門家確認を取るか、保守側に倒して同意対象に含めるか。#4944 D3
- [ ] **Stripe の根拠を「同意」に確定するか** — CBPR 依拠なら §28(3) の年 1 回確認と 7 項目情報提供が永続し、2027-07 の認証失効監視も要る。#4944 D4
- [ ] **ap-northeast-1 移設の可否** — 義務自体は消えないが「米国」の語は消せる。#4944 D5
- [ ] **privacy.html 第 10 条の「移転される情報の範囲」が実態より狭い** — S3 のアバター画像と Cognito のメールアドレスが抜けており DPIA §6 の表と一致しない。修正は改定日 bump = 全利用者の再同意発火を意味するため、上記の同意再設計と同一の改定にまとめる。#4944 AC4
- [ ] **AWS 契約文言の解釈確認** — CA §1.4 は「サービスを維持もしくは提供するために必要な場合を除き」という留保付きの不作為約束であり、PPC の「取り扱わない旨が定められており」と文言が完全一致するわけではない。クラウド例外の成立は事業者の自己判断である
- [ ] **他の法務由来 UI への横展開** — Cookie 説明・利用規約本文・アカウント削除フローの説明も同じ構造の問題を抱えうる
