# 返金・課金インシデント runbook

対象: 「間違えて買った」「二重に請求された」「身に覚えのない請求がある」と顧客から言われたとき。
**最初の返金要求が来た時点で手順を考え始めない**ために置く（#4581 / EPIC #4580 G2）。

関連: `docs/design/billing-redesign/phase1-cancellation-requirements.md`（無返金の設計根拠）/
`docs/design/billing-redesign/contract-state-matrix.md`（契約状態 SSOT）/
`src/lib/server/services/stripe-service.ts`（webhook handler）/ `site/tokushoho.html`（特商法表記）

---

## 0. まず前提を取り違えない — 「返金しない方針」と「請求ミスの是正」は別

顧客提示物は**返金を行わないと明記**している。

| 提示物 | 記述 |
|---|---|
| `site/tokushoho.html` | 「返金は行いません」 |
| `site/faq.html` | 「返金は行っておりません」 |
| 利用規約 第7条5（`labels.ts` SSOT） | 「日割り計算による返金は行いません」 |

これは **「解約したから日割りで返せ」に応じない**という方針である（設計根拠:
`phase1-cancellation-requirements.md` FR-2 = Stripe デフォルト無返金 / 解約料規制の回避）。

**請求ミスの是正はこれとは別物**。二重課金・意図しない課金・こちらの不具合による課金は、
「返金しない方針」の対象ではない。**この 2 つを混ぜて「返金はできません」と返すと、
非を認めない対応になる。**

> **判断に迷ったら止まる**: 「方針としての返金拒否」に当たるのか「請求ミスの是正」なのかが
> 判別できないケースは、**オーナー判断を仰いでから返信する**。誤って「返金しません」と
> 送ってしまうと撤回が難しい。

## 1. 最初の 10 分（受付〜一次返信）

1. **顧客の主張を 1 行に落とす** — 「二重請求」「解約したのに請求」「覚えのない請求」「操作ミスで購入」のどれか
2. **Stripe Dashboard で該当顧客を特定する**
   - Customers → メールアドレスで検索（顧客が名乗ったアドレスと Stripe 上のアドレスが違う場合がある）
   - 該当 Customer の **Payments** タブで請求履歴を、**Subscriptions** タブで契約状態を見る
3. **一次返信を送る**（調査前でよい。無言の時間を作らない）
   - 「請求の内容を確認しています。◯営業日以内にご連絡します」
   - **この時点で返金の可否を約束しない**

---

## 2. 事実の確定 — Stripe が正、アプリ DB は従

**課金の事実は Stripe が SSOT**。アプリ側 DB（`tenants` の `stripeCustomerId` /
`stripeSubscriptionId` / `plan` / `status`）は webhook で追随している**写し**である。

食い違ったときは **Stripe を正とし、アプリ側を合わせる**（逆をやらない）。

### 2.1 二重課金の判定

Stripe Dashboard → 該当 Customer → Payments:

- **同一金額・近接時刻の成功 charge が 2 件以上あるか**
- Subscriptions が **2 本以上 active になっていないか**（重複 Checkout の典型）
- 片方が `incomplete` / `past_due` で終わっていないか（実際には 1 回しか請求されていない場合がある）

**「請求書が 2 通届いた」= 二重課金とは限らない**。Stripe は失敗 → リトライでも通知を送る。
**実際に成功している charge の件数**を見る。

### 2.2 アプリ側の状態を見る

**`/ops` には契約状態をテナント単位で引く画面が無い**（現状 `/ops` 配下は analytics /
business / cohort / costs / export / pmf-survey / revenue のみ）。

したがってアプリ側の確認は以下になる:

- 顧客に**アプリの「プラン・お支払い」画面のスクリーンショット**を送ってもらう（最も速く、DB を触らない）
- それでも足りない場合のみ、DB の該当テナント行を **読み取りだけ**で確認する

> **本番 DB を書き換えて辻褄を合わせない**（§5）。

---

## 3. 返金を実行する

**Stripe Dashboard から行う。アプリ側に返金操作は無い。**

1. Stripe Dashboard → Payments → 該当 charge を開く
2. **Refund** → 全額 / 一部を選ぶ
   - **二重課金**: 重複した側を**全額返金**
   - **意図しない購入で、まだ利用実態が無い**: 全額返金を基本とする（オーナー判断）
   - **利用期間がある**: **日割り返金は方針として行わない**（§0）。例外はオーナー判断
3. Reason は `duplicate` / `requested_by_customer` / `fraudulent` から実態に合うものを選ぶ
4. **重複した Subscription が残っている場合は、返金と別に subscription を cancel する**
   （返金は請求を戻すだけで、契約は止まらない）

---

## 4. 返金後にアプリ側で何が起きるか — **自動では何も起きない**

**重要**: アプリは Stripe の返金イベントを購読していない。

`stripe-service.ts` の `handleWebhookEvent` が処理するのは以下の **5 種のみ**:

```
checkout.session.completed / invoice.paid / invoice.payment_failed
customer.subscription.updated / customer.subscription.deleted
```

**`charge.refunded` は含まれない。** したがって:

| 操作 | アプリ側の反応 |
|---|---|
| charge を返金しただけ | **何も起きない**。プランは有料のまま |
| subscription を cancel した | `customer.subscription.deleted` が届き、契約が終端へ収束する |

→ **返金してプランも落とすなら、subscription の cancel まで行う**。返金だけで終えると、
**顧客はお金を返されたまま有料機能を使い続ける**（意図した結果ならそれでよいが、意図の確認が要る）。

### 4.1 顧客に届くもの

- **Stripe から返金通知メール**が自動で届く（Stripe の設定に依存）
- **アプリからは何も送られない**。プラン変更を伴う場合、顧客が気づくのは次にアプリを開いたとき
  → **返金対応のメールで、プランがどうなるかを自分の言葉で伝える**

---

## 5. やってはいけないこと

- **本番 DB を手で書き換えて辻褄を合わせる**。Stripe と DB が食い違ったら、
  Stripe を正として**アプリ側の webhook 経路で収束させる**（`customer.subscription.*` を発火させる）
- **「返金は行っておりません」を請求ミスに対して返す**（§0）
- **調査前に返金可否を約束する**（一次返信では期限だけ伝える）
- **返金だけして subscription を放置する**（§4）
- **顧客のメールアドレスだけで本人確認を済ませる**。契約者と問い合わせ元が違うことがある

## 6. 顧客への返信テンプレート

用語は `terms.ts` / `labels.ts` の SSOT に合わせる。特に **「解約」（サブスクの自動更新停止）と
「退会」（アカウント削除）を混同しない**（#4496 で是正した区別）。

### 6.1 一次返信（調査中）

```
このたびはご不便をおかけし申し訳ございません。
ご請求の内容を確認しております。確認でき次第、改めてご連絡いたします。

がんばりクエスト サポート
ganbari.quest.support@gmail.com
```

### 6.2 二重課金だった場合

```
確認いたしましたところ、お客さまのご請求が重複しておりました。
重複していた◯◯円を全額ご返金いたしました。ご返金は決済会社を通じて
お客さまのお支払い方法へ戻ります（反映までに数営業日かかる場合があります）。

なお、重複していたご契約は停止済みです。現在ご利用中のプランは
これまでどおりご利用いただけます。

ご迷惑をおかけしました。
```

### 6.3 方針として返金できない場合（解約に伴う日割り等）

```
ご連絡ありがとうございます。
お支払いいただいた期間の終了日までは、有料プランの機能をそのままご利用いただけます。
期間の途中で解約された場合の日割りでのご返金は承っておりません
（特定商取引法に基づく表記に記載しております）。

期間の終了後は無料プランへ切り替わり、お子さまの記録は残ります。
```

> 「解約」と書くべきところを「退会」と書かない。**退会（アカウント削除）はデータが消える別の操作**。

## 7. 記録

対応が終わったら、**次に同じことが起きたときに読む人のために**以下を残す:

- 何が起きたか / Stripe 上の判定根拠（charge 件数・subscription 本数）
- 返金額と reason / subscription を止めたか
- **手で補った操作があればそれ**（自動で追随しなかった箇所 = この runbook の改訂候補）

`docs/runbooks/` は運用の SSOT なので、**手順が実態と違ったらこのファイルを直す**。
